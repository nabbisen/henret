# v0.1.0 Architecture Review — Resolution (v0.2.0)

An external architecture review of v0.1.0 (2026-06-04) confirmed the
positioning and structure but identified seven must-fix issues before a
clean public release. All seven are resolved in v0.2.0.

| # | Must-fix | Resolution | Where |
|---|---|---|---|
| 1 | Lifecycle docs did not match the model (`new`/`yielded` are runnable) | Docs rewritten as the actual transition table; runnability of `new`/`yielded` stated explicitly | `Henret/Actor/Task.lean`, `docs/guided-tour.md`, `examples/01` (RFC 018) |
| 2 | Actor ownership not represented | `taskOwner : TaskId → Option ActorId` in `RuntimeState`, written at spawn | `Henret/Scheduler/Model.lean` (RFC 014) |
| 3 | Ownership uniqueness claimed but not proven | `WellFormed` invariant + `step/run_preserves_wf` + `reachable_wf`; disjointness corollaries derived | `Henret/Proofs/Invariants*.lean` (RFC 013) |
| 4 | `tick` could enqueue stale non-sleeping timer tasks | `tick`'s woken list filtered to genuinely `sleeping` tasks; demo regression added | `Henret/Scheduler/Model.lean` |
| 5 | Logical time not stored; `tick 100; tick 3` accepted | `now : Nat` field; tick guarded monotone; `tick_backwards_invalid`, `step_clock_monotone` | `Model.lean`, `Proofs/Timers.lean` (RFC 015) |
| 6 | `step_invalid_unchanged` documented but missing | Theorem added, full ten-operation case analysis | `Henret/Proofs/Lifecycle.lean` (RFC 016) |
| 7 | Stale "RFC 010 proposed/future" wording | Consistency sweep; standard native-boundary wording everywhere | RFC 018 |

The review's six recommended RFCs (013–018) were all written and implemented
in v0.2.0; see `rfcs/done/`. The review's strategic guidance — "the next
maturity step should be invariant discipline, not feature expansion" — set
the v0.2.0 scope.
