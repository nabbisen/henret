# Migration: v0.26.0 → v0.27.0 (RFC 091 — Actor-Owned Resources)

## Breaking change: `ResourceRecord.owner`

The resource-ledger owner type changed from `TaskId` to a sum type:

```text
-- before (RFC 057)
structure ResourceRecord where
  owner : TaskId
  state : ResourceState

-- after (RFC 091)
inductive ResourceOwner where
  | task  : TaskId  → ResourceOwner
  | actor : ActorId → ResourceOwner

structure ResourceRecord where
  owner : ResourceOwner
  state : ResourceState
```

**Downstream impact (theorem/term users):**

- A task-owned record literal `⟨t, st⟩` becomes `⟨.task t, st⟩`.
- The three task-keyed `WellFormed` fields were replaced by owner-generic ones:
  `resource_owner_spawned → resource_owner_valid`,
  `allocated_owner_nonterminal → allocated_owner_live`,
  `closing_owner_terminal → closing_owner_closed` (read via `OwnerValid` /
  `OwnerLive` / `OwnerClosed`). The **old statements are preserved** for task
  owners as compatibility corollaries `WellFormed.allocated_owner_nonterminal`
  and `WellFormed.closing_owner_terminal`, so RFC 057 proofs that consume them
  keep working after substituting `.task t` into their record hypotheses.
- `WellFormed.status_irrel` (RFC 055) became `WellFormed.runtimeStatus_irrel`:
  the resource invariants now depend on `actorStatus` (for actor owners), so an
  arbitrary `actorStatus` change is no longer well-formedness-irrelevant —
  `closeActor` must mark actor-owned resources to preserve `WellFormed`.

## New surface

- New op `acquireActor (a : ActorId)` (RuntimeOp count 27 → 28).
- `release t r` is now invalid for actor-owned resources (Tier 1).
- `closeActor a` now additionally marks actor-`a`-owned `allocated` resources
  `closing`.

No new project axioms; all RFC 091 theorems are STD (`propext`, `Quot.sound`)
or STD_C.
