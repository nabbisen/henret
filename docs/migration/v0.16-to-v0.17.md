# Migration: v0.16.x → v0.17.0 — structured cancellation & shutdown (RFC 055)

**Grammar change.** Additive across three types:

- two new enums, `ActorStatus` (`active | closed`) and `RuntimeStatus`
  (`running | shuttingDown | stopped`);
- `RuntimeState` gained two fields, `actorStatus : ActorId → ActorStatus`
  and `runtimeStatus : RuntimeStatus`;
- `RuntimeOp` gained `closeActor`, `shutdown`, and `stopWhenIdle`
  (now **21** constructors).

The new fields are *admission-status* fields. They are **`WellFormed`-
irrelevant**: no invariant field mentions them, so the 28-field base
safety contract is byte-for-byte unchanged (`WellFormed.runtimeStatus_irrel`).

The only behavioral change to pre-existing operations is that three now
carry an **admission guard**:

- `spawn a` requires `runtimeStatus = .running` (rejected during shutdown);
- `send t b m` is rejected when `actorStatus b = .closed`;
- `inject a m` is rejected when `runtimeStatus ≠ .running` or
  `actorStatus a = .closed`.

In the initial state (`runtimeStatus = .running`, every actor `.active`)
these guards never fire, so any program that never issues `closeActor`,
`shutdown`, or `stopWhenIdle` behaves exactly as before.

## What changed

RFC 055 adds *structured shutdown*, a safety-only feature (no fairness,
liveness, or guaranteed-quiescence claim). See
[`docs/shutdown-semantics.md`](../shutdown-semantics.md). Subtree
cancellation is **not** new — it is the existing `cancelTree` (RFC 039).

## Impact on downstream code

You need to act only if your code:

1. exhaustively matches over `RuntimeOp` (add three arms), or
2. constructs a `RuntimeState` literally (set the two new fields), or
3. exhaustively matches over `TraceEvent` (add three arms).

Code that consumes the public theorems or uses `run`/`step`/`runTrace`
opaquely is unaffected.

## What to update

### Exhaustive matches over `RuntimeOp`

Add arms for the three new operations. None of them touch task state,
ownership, parenthood, or the ready queue, so for most analyses they are
no-ops on the dimension you care about:

```lean
match op with
| ...existing arms...
| .closeActor a  => ...   -- flips actorStatus a to .closed (if it exists)
| .shutdown      => ...   -- sets runtimeStatus := .shuttingDown
| .stopWhenIdle  => ...   -- sets runtimeStatus := .stopped iff quiescent
```

### Constructing a `RuntimeState` literally

Prefer `RuntimeState.init` or `{ s with ... }`. If you build one field by
field, add:

```lean
actorStatus   := fun _ => .active
runtimeStatus := .running
```

### Exhaustive matches over `TraceEvent`

Add `.actorClosed a`, `.shutdownBegun`, `.stoppedWhenIdle`.

## What did *not* change

- The 28-field `WellFormed` invariant and `reachable_wf`.
- Every pre-existing per-operation theorem (now stated for the
  guard-passing case; the guards only *add* invalid cases, which are
  no-ops by `step_invalid_unchanged`).
- The single-worker bridge relation `BridgeState` and `toQOps` for every
  pre-existing operation in the guard-passing case.
- The axiom budget: zero project axioms; the new headline theorems use
  only `{propext, Quot.sound}`.
