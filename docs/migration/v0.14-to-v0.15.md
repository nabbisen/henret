# Migration: v0.14.x → v0.15.0 — supervision restart (RFC 049)

**Grammar change.** Additive across three types:

- `TaskState` gained a constructor `failed` (now 10 constructors);
- `RuntimeOp` gained `fail` and `restartOne` (now 18 constructors);
- `RuntimeState` gained a field `restartOf : TaskId → Option TaskId`.

All three changes are **additive**: the behavior of every pre-existing
operation and the shape of every pre-existing `WellFormed` field are
unchanged. The only breaks are mechanical and compiler-caught.

## What changed

RFC 049 added one-for-one supervision restart. A task can now *fail*
(terminate abnormally, distinct from an intentional `cancel`), and a
supervisor can *restart* a failed child as a fresh task, with provenance
recorded in the new `restartOf` map. See
[`docs/supervision-restart.md`](../supervision-restart.md).

## Impact on downstream code

You need to act only if your code exhaustively matches over `TaskState`
or `RuntimeOp`, or constructs a `RuntimeState` literally. Code that
consumes the public theorems or uses `run`/`step` opaquely is unaffected.

## What to update

### Exhaustive matches over `TaskState`

Add a `.failed` arm. It is terminal, so it behaves like `.cancelled` for
most purposes:

```lean
match st with
| ...existing arms...
| .failed => ...   -- terminal, like .cancelled
```

`TaskState.isTerminal` already returns `true` for `.failed`
(`isTerminal_failed`), so logic keyed on `isTerminal` needs no change.

### Exhaustive matches over `RuntimeOp`

Add `.fail` and `.restartOne` arms:

```lean
match op with
| ...existing arms...
| .fail t              => ...
| .restartOne p c a    => ...   -- parent, failedChild, actor
```

`fail` mirrors `cancel`'s cleanup (lands in `.failed`); `restartOne`
mirrors `spawnChild` (fresh task) plus a `restartOf` update.

### Constructing `RuntimeState`

If you build a `RuntimeState` literally (rather than via
`RuntimeState.init` and `step`), add the `restartOf` field. The initial
value is the empty map:

```lean
{ ... , restartOf := fun _ => none }
```

`RuntimeState.init` already sets this; only hand-rolled literals need it.

## What did not change

- The 28-field `WellFormed` invariant — no field mentions `restartOf`
  (`WellFormed.restartOf_irrel` makes this explicit), and all field
  statements are unchanged.
- The behavior of every pre-existing operation.
- The axiom budget — the new theorems depend only on `propext`,
  `Classical.choice`, `Quot.sound`.
- All existing proof/trust/test classifications.
- The conformance suite — the golden traces are unaffected, because the
  new operations do not alter existing observable behavior.

The restart-provenance facts live in a **separate** `RestartWellFormed`
structure, so the base safety contract is untouched.
